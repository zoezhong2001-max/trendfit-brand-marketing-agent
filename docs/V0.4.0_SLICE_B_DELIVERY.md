# TrendFit v0.4.0 Slice B：品牌资产工作区

## 本轮结果

Slice B 把 Slice A 的品牌资产契约接入了一个可操作页面，入口为：

```text
/brand-assets
```

页面服务于“商品库平台产品经理”面试叙事：品牌档案不再只是品牌语气和受众描述，而是下钻为可管理、可核验、可供营销链路消费的泛商品资产。

## 已实现能力

1. 多品牌切换：Petlibro、奈雪的茶、BreezeCare（合成品牌）。
2. 泛商品建模：统一承载实体商品、菜单商品和服务商品。
3. 商品检索与组合筛选：名称 / 场景 / ID、商品类型、营销就绪状态。
4. 状态看板：资产总数、可进入营销、待补充核验、失效 / 阻断。
5. 商品资产主从详情：生命周期、人群场景、变体、结构化属性、可售及履约范围。
6. Claim 管理：可用表达、适用条件和执行护栏。
7. 事实依据链路：事实 / 假设标识、来源 ID、页码 / 行号定位、读取方式。
8. 版本快照：品牌版本、商品版本、来源批次和不可变内容指纹。
9. 前端加载时复用 Slice A 验证器；不符合契约的数据进入错误态，不静默展示。
10. 响应式布局：桌面双栏工作台，窄屏转为上下结构。

## 数据与真实性边界

- 页面数据全部来自 `synthetic_demo` 合成样例。
- 奈雪与 Petlibro 仅作为商品形态演示，不将样例字段描述为品牌真实经营事实。
- 没有实现文件上传、自动抽取、在线 AI 创编、真实投放或真实 ROI 提升。
- `eligible` 表示样例规则下“具备进入下游营销流程的条件”，不表示广告一定能过审或取得效果。

## 面试演示路径（3–5 分钟）

1. 先选奈雪：说明同一品牌下，活动商品、待核验概念和历史失效商品如何共存。
2. 筛选“可进入营销”：展示生命周期、可售范围、Claim 与证据共同决定状态，而非主观评分。
3. 切换到“依据链路”：解释为何 AI 应区分事实和假设，并让关键字段可回溯。
4. 切换到“版本快照”：说明下游创编应绑定不可变快照，避免品牌资料更新后无法复盘。
5. 切换 BreezeCare：说明同一套底层结构如何覆盖服务商品与区域履约约束。

## 后续 Slice C 建议

下一步不建议先堆更多页面，而应让商品库进入营销工作流：

1. 新建“选品任务”：输入营销目标、市场、渠道和时间窗口。
2. 先做规则过滤：生命周期、可售范围、Claim、硬阻断。
3. 再做可解释排序：场景匹配、证据完整度、创意资产覆盖度。
4. 输出选择理由和未选原因，不伪造预测 ROI。
5. 将结果固化为选品快照，供后续 Brief / 创编消费。

# TrendFit v0.4.0 Slice C：可解释智能选品

## 本轮结果

Slice C 将品牌商品库接入了第一个下游营销工作流。页面入口：

```text
/selection-tasks
```

工作流不是“让模型随便推荐商品”，而是把智能选品拆成两个责任清晰的阶段：

1. 确定性规则过滤：生命周期、营销就绪状态、可售 / 履约范围、Claim 和硬阻断。
2. 可解释候选排序：场景匹配、价值主张、依据完整度和变体可执行性。

只有先通过硬规则的商品才能进入排序。

## 已实现能力

- 选择广告主品牌。
- 配置转化增长、品牌认知或老客经营目标。
- 配置目标市场、营销渠道、任务时间窗口、核心场景和推荐数量。
- 实时执行硬规则过滤。
- 展示推荐商品及四项确定性匹配信号。
- 根据目标切换透明的排序权重。
- 展示每个未选商品的具体排除原因。
- 无合格商品时返回空结果，不绕过约束强行推荐。
- 生成确定性的选品快照 Key。
- 选品快照绑定品牌资产快照和商品版本。
- 从候选商品回跳品牌资产页，并定位到对应商品。
- 任务配置变化后，旧快照自动失效。

## 当前规则

### 硬规则

1. 商品生命周期不能为 retired / archived。
2. `marketing_readiness` 必须为 `eligible`。
3. 目标市场、渠道和任务时间窗口内必须存在 `available` 记录。
4. 商品不得存在 `hard_blockers`。
5. 商品引用的 Claim 必须存在且完成确认。

### 排序信号

- 场景匹配。
- 价值主张属于已确认事实。
- 商品与价值字段的依据引用完整。
- 至少存在一个结构化变体。

页面显示的 0–100 是规则匹配度，不是 CTR、CVR、GMV 或 ROI 预测。权重只用于演示不同营销目标下的候选排序机制。

## 快照结构

选品快照包含：

- 任务配置。
- 输入品牌资产快照 ID。
- 入选商品 ID、版本和规则匹配度。
- 未选商品 ID、版本和排除原因。
- 由全部内容稳定生成的 Snapshot Key。

这使 Brief、创编或投放诊断能够消费一次固定选择，而不是始终读取可能变化的“最新商品资料”。

## 面试演示路径（5 分钟）

1. 默认打开奈雪任务：解释任务目标、市场、渠道和时间窗口是选品输入，不是一个自由文本 Prompt。
2. 查看推荐候选：轻烘焙组合通过硬规则，并展示四项匹配信号。
3. 查看未选原因：下班轻乳茶因为信息待核验且门店范围未知被过滤；夏日限定因为生命周期和有效期被过滤。
4. 将渠道改为电商：结果变为空，说明系统不会为“必须给答案”而越过可用范围。
5. 切换 BreezeCare：同一套能力可处理服务商品和区域履约。
6. 生成选品快照：说明下游创编消费固定版本，便于复盘和审计。

## 与岗位 JD 的映射

| 岗位能力 | 可展示的产品判断 |
| --- | --- |
| 商品生命周期与营销诉求 | 时间窗口、生命周期和可用范围共同参与选品 |
| 管理提效与效果优化 | 自动过滤不可执行候选，把运营精力集中在合格商品 |
| 智能选品 | 将约束过滤与智能排序解耦，保留解释和人工判断空间 |
| 平台化建设 | 选品引擎只依赖通用商品、Claim、Availability 和 Snapshot 契约 |
| 数据驱动 | 权重和规则明确可观测，后续可用真实实验校准，而非先编效果数字 |
| Ownership | 空结果、未选原因、版本绑定和演示数据边界都被显式处理 |

## 真实性边界

- 使用的是合成数据与确定性规则。
- 没有连接真实广告账户、商品中心或投放平台。
- 没有训练排序模型，也没有使用历史转化标签。
- 没有宣称提升 CTR、CVR、GMV 或 ROI。
- 快照当前是浏览器内演示状态，没有持久化数据库和权限系统。

## 后续 Slice D 建议

将选品快照接入“受控智能创编”：

1. 选择目标商品快照和目标渠道。
2. 只允许模型使用已确认 Claim 与 Evidence。
3. 输出文案时逐句标记来源和风险状态。
4. 遇到待核验字段时降级为提问或人工审核，不自动补事实。
5. 记录 Prompt、模型版本、输入快照和输出审核结果。

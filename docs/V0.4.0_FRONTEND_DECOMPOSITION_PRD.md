# TrendFit v0.4.0 前端组件拆分 PRD / 技术设计

状态：用户已确认；2026-09-21 已完成实施与自动验收。

本轮性质：工程结构收口，不新增产品能力，不改变用户可见行为。

## 1. 背景

`web/components/trendfit-app.tsx` 当前约 1,563 行、54 KB，同时承载：

- 演示数据启动、错误边界与本地恢复；
- 内部 hash 路由与页面分发；
- 当前品牌、编辑器、反馈、历史记录、提示和未保存状态；
- 热点雷达首页；
- 品牌档案；
- 热点详情与品牌参与判断；
- Brief 工作台；
- 品牌与 Brief 编辑；
- 反馈、历史记录、未保存离开等弹窗。

功能已经可用，但多个 Agent 修改不同功能时仍会集中改动同一个文件，增加合并冲突和回归定位成本。v0.4.1 还将涉及证据审阅、解析评测和更多跨对象状态，因此需要先把现有边界拆清楚。

## 2. 目标

1. 将页面、业务组件、弹窗和状态逻辑拆到明确目录；
2. 将 `trendfit-app.tsx` 收敛为启动、错误边界和工作台组装入口；
3. 让热点、品牌、Brief、反馈可以由不同 Agent 在不同文件中维护；
4. 保持现有数据合同、路由、localStorage、视觉和交互行为不变；
5. 每个实施切片都能独立构建、测试和回滚。

## 3. 非目标

- 不新增页面、字段、筛选、AI 能力或真实数据；
- 不改变四个一级入口及统一工作台信息架构；
- 不把 hash 路由迁移到新的路由框架；
- 不引入 Redux、Zustand 或新的状态管理依赖；
- 不重写 `lib/data.ts` 的业务合同；
- 不实现统一工作台 P1；
- 不调整品牌型 / 商品型 Brief 规则；
- 不修改视觉方向和页面文案，除非拆分导致原文无法复用。

## 4. 必须保持不变的行为

### 数据与版本

- 启动时继续校验 manifest、哈希、版本和对象引用；
- 校验失败时停止展示业务判断；
- 合成演示、未核验和本机保存提示继续显示；
- 人工反馈继续追加保存，不覆盖模型判断；
- 品牌修改后旧 Assessment / Brief 继续标记待重评。

### 路由与上下文

- `/`、`#/brands`、`#/trends/:id`、`#/briefs/:id` 行为保持不变；
- `/brand-assets` 与 `/selection-tasks` 继续使用现有独立页面；
- URL 中的品牌参数与本机品牌上下文继续同步；
- 切换品牌时，热点事实不变；
- Brief 不存在对应品牌版本时，继续回到热点详情。

### 编辑与反馈

- 未保存离开继续提供保存、放弃和继续编辑；
- 浏览器关闭或刷新继续触发未保存提醒；
- 品牌和 Brief 编辑继续创建本机副本，保留基准版本；
- 存储失败不能显示保存成功；
- 反馈理由继续必填；
- 历史记录和导出行为保持不变。

## 7. 状态边界

首轮不引入全局 Provider。`Workspace` 仍拥有现有共享状态，并通过明确 props 传给页面组件：

- `data`、`store`、`brand`、`profile`、`route`；
- 页面导航与品牌切换回调；
- 打开编辑、反馈和历史弹窗的回调；
- 保存结果、错误与提示状态。

只有在页面拆分稳定后，才把以下逻辑抽成 Hook：

- `useWorkspaceRoute`：hash 路由、浏览器前进后退、页面跳转；
- `useWorkspaceStorage`：读取、校验、保存和恢复本机 Store；
- `useUnsavedGuard`：脏状态、离开确认和 `beforeunload`。

这样可以把“移动 JSX”和“重构状态行为”分开验证。

## 11. 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 大量移动导致难以评审 | 按切片、按页面提取，每次只移动一个责任边界 |
| props 过多 | 首轮接受显式 props；页面稳定后再判断是否需要 Context |
| 拆分时顺手改变行为 | PRD 明确行为冻结；新功能另立 PRD |
| localStorage 错误语义变化 | 存储 Hook 最后提取，并复用现有校验与错误文案 |
| 多 Agent 同改入口文件 | 先同步状态，再按切片串行修改入口；提取后按目录并行 |
| 为追求短文件造成碎片化 | 行数仅作提示，组件必须有独立业务责任才拆分 |

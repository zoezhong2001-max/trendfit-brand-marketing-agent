# v0.3.0 · Radar Room 本地网站

状态：STEP 04 完成。本版本是可操作的本地网页 Demo，不代表实时热点采集或在线模型生成已经接通。

## 已完成的产品链路

`共享话题池 → 品牌切换 → 适配判断 → 证据与反对理由 → 热点引申 Brief → 人工反馈`

- 默认奈雪的茶，可切换 Petlibro；同一话题事实不因品牌变化而改变。
- 首页支持搜索、品牌结论、信号类型和候选/日历筛选。
- 话题详情分开展示热点事实与品牌判断；合成来源、未知时间和证据缺口均明确标记。
- 推荐与改造结论可以打开对应 Brief；不推荐结论没有 Brief 入口。
- Brief 可以编辑、复制、导出；保存的是本机修订，基准草稿与来源链保留。
- 品牌档案可以编辑本机副本；修改后旧评估和 Brief 显示“待重评”，不会假装已经重新推理。
- 保留、淘汰、要求补证与 Brief 修改均保存为人工事件，模型原结论不被覆盖。

## 数据边界

本版使用 3 个中国市场合成话题、2 个品牌和 6 条跨品牌判断。所有话题均为 `synthetic_demo / unverified`；“长假前的宠物照护安排”属于 `calendar` 支线，不能升级为实时热点推荐。网页没有真实来源链接、实时刷新、在线生成、登录、云端同步或营销发布能力。

网站载入时会核对 manifest 文件集合、内容哈希、数据版本、ID 关系、品牌×话题矩阵、Brief 来源与状态。校验失败时停止展示判断。

## 本地运行与演示

```bash
cd web
npm ci
npm run dev
```

推荐面试路径：奈雪 → “下班后十分钟回血” → 查看话题事实和品牌判断 → 打开 Brief → 编辑并填写修改理由 → 切换 Petlibro，展示同一话题变为不推荐且没有 Brief。

浏览器数据仅保存在当前设备。开发验收产生的测试记录不属于仓库展示数据。
